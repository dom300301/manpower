# 官職等配置審核系統　需求檢視與架構規劃

檢視日期：2026-10-31　　狀態：**請確認後再動手寫程式**

> 一句話結論：**可以做，而且比銓敘部試算表做得細。** 計算公式已全部取得並以 PoC 驗證可程式化；真正的難點不在算式，而在三件「資料」：機關類別歸類、主管／非主管與單位層級的判定、以及各機關過去經考試院同意的例外紀錄。這三件需要貴處提供或人工確認，其餘可由程式完成。

| 第 9 條 | 新增：三級署、局**參議**上限 ＝（幕僚長＋一級業務單位主管）÷2，派出單位主管及所屬機關首長每滿 5 人再加 1；中央二、三級配置於一、二級單位主管間之**簡任非主管 ≤ 二級單位主管員額 × 7/10**；二級機關高階參贊職務的計算基準納入幕僚長與輔助單位主管（不含人事、主計、政風） | 二級機關參贊職務只以一級業務單位主管＋三級機關首長為基準；三級機關無明文 |
| 第 12、13 條 | 不符者於**下次修編時修正**，特殊原因得報銓敘部同意延後；組織結構或業務性質特殊得敘明理由報考試院同意 | 大致相同 |

總說明另載明兩項對本系統很重要的實務原則（第 9 條說明五）：
1. 簡任非主管職稱原即未符核議標準者，修編時若**比例維持原有或更低**，始同意核備，並請機關下次修編逐步調整。→ 這正是您第三層面「往符合方向邁進」的法規依據。
2. 研究員等任用、聘任雙軌職稱不計入簡任非主管；公職律師、消費者保護官亦不計入。

## 四、三個層面的需求逐一檢視

### 層面一：資料獨立於組織法查詢系統

- 合乎邏輯，但**不建議「複製一份 Excel」**。兩套系統各抱一份資料，日後法規更新時會不同步，等於多一條路。
- 建議：資料只有一份（`org-compare/data/` 總表，由既有更新流程維護），本系統放在 `grade-check/` 資料夾，**讀同一份總表**，另外維護自己的規則檔與對照表。雲端硬碟可另開「官職等配置審核」資料夾只放成品（網頁、檢核報告）。
- 這樣組織法查詢系統不受影響，更新流程也只需做一次。

### 層面二：審核機制（比銓敘部試算表做得細）

可做到，且每一條規則都能寫成「規則編號、法條、計算式、實際數字、門檻、差距、結論」逐筆輸出。規則清單：

| R2 委任比率 ≥ 下限 | 同上 | 全自動 | 同上 |
| R3 跨列官等的拆算 | 第 6 條 | 全自動 | 無（備註解析已可行） |
| R4 委任一至三職等最低員額 | 第 7 條第 1 項 | 全自動 | 無 |

提醒兩點：
1. 系統是**輔助審查**，正式認定仍是銓敘部與考試院；報告上要寫清楚。
2. 應區分「準則明文」（硬性）與「考試院核議標準」（彈性、可敘明理由），兩者在報告中分級呈現，避免把彈性標準講成違規。

### 層面三：調整方案與補充說明

分成三個子功能，都做得到，但要先講清楚界線：

**(a) 最小調整建議**
- 以「改動最少員額就達標」為目標，列出可動的職稱（排除組織法律所定、首長副首長幕僚長、經考試院同意者），試算把哪幾個職稱降一個官等或改列「委任或薦任」即可達標，並給出兩三組方案。
- 這是整數規劃問題，規模小（一個機關幾十個職稱），用簡單的貪婪法即可，不需複雜套件。
- 界線：系統只提供「數學上可行」的方案，**不判斷現職人員能否安置**；這要由機關說明。

**(b) 趨勢判定（原本就不符的機關）**
- 比較修編前後：各項比率的方向（改善／惡化／持平）與距門檻的差距（百分點、折合人數）。
- 依總說明的銓敘部實務：「維持原有比例或更低者始同意核備」，系統可直接給出「依此原則可／不可核備」的初判。
- 這一項有明確法規文字依據，建議列為正式功能。

**(c) 補充說明清單**
- 依不符的規則自動產生「請機關補充說明」的題目，理由類型對應第 13 條：配合政府政策之組織精簡或人員移撥、組織結構特殊、業務性質特殊；並列出應附的佐證（例如核定的政策計畫、移撥函、業務量數據、同類機關比較）。
- 界線：系統提示「理由類型」與「需佐證事項」，**不替機關撰寫理由**；同時可附上同層級同類機關的比率分布（組織法查詢系統已有），讓審查者判斷「核心工作確實與一般機關不同」是否成立。

### 整體邏輯上的兩點建議調整
1. **加一個「適用版本」的判斷**：資料是 2026 年 10 月的編制表，但準則是 114 年 12 月才修正，多數編制表是修正前核備的。報告要同時顯示「舊制合不合」與「新制合不合」，才不會把依第 12 條合法維持舊表的機關誤判為違規。
2. **審查單位與銓敘部的判準分開呈現**：準則與考試院標準一欄，人事總處內規（若提供）另一欄，避免混用。

## 五、建議架構

```
org-compare/data/總表.xlsx ──┐
grade-check/rules/           │   （規則與對照表，JSON／CSV，可直接用 Excel 編）
  ├ ratio_table.json         │   附表三（新制＋舊制）
  ├ title_category.json      │   附表二職稱屬性＋主管職稱表
  ├ agency_category.csv      │   機關類別（程式初判→人工確認）
  ├ agency_flags.csv         │   雙軌、駐外、軍文併用、例外核備紀錄
  └ grade_table.json         │   職務列等表（取得後）
                             ▼
grade-check/check_grades.py ─── 規則引擎：每機關輸出逐條檢核結果（JSON）
                             ▼
grade-check/build_site.py ──── 產生 output/index.html（離線單檔，亦可上 GitHub Pages）
```

網頁功能：
1. 查機關 → 逐條檢核結果（符合／不符／需人工確認）、計算明細、同類機關分布。
2. **模擬修編**：把擬修的編制表貼進網頁表格（或上傳 Excel），用同一套規則即時重算，顯示修編前後比較與趨勢判定。計算在瀏覽器內以 JavaScript 完成，不需伺服器，資料不外傳。
3. 調整方案與補充說明清單，可匯出 Word／Excel 附在審查意見。

技術選擇：與組織法查詢系統相同，**Python 建檔＋離線單檔 HTML**。理由：貴處已熟悉此流程、不需伺服器、可放 GitHub Pages 公開。不需要 Flask 後端（沒有多人寫入需求），也不需要 PyScript（規則用 JavaScript 重寫一次即可，檔案小、載入快）。規則會在 Python 與 JavaScript 各寫一份，以同一批機關互相核對確保一致。
