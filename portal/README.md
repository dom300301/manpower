# 組編人力整合入口（第一層，概念驗證版）

把現行四個查詢系統（第二層）整合成一個上層入口，以「機關代碼」串接。
**本資料夾不修改任何現行系統**，只唯讀取用它們已產出的 `output/index.html`。

## 三層架構

| 層 | 內容 | 現況 |
|---|---|---|
| 第一層　整合入口 | 本資料夾：系統架構、機關一頁式、部會總覽、四系統並列、資料接入與下一步 | 概念驗證完成，尚未上線 |
| 第二層　專題系統 | `org-compare/`、`grade-check/`、`contract-manpower/`、`staffing/` | 維持原狀 |
| 第三層　共用資料 | 機關主檔（機關代碼）、人力統計表、機關沿革對照、名詞口徑定義 | 主檔仍在 org-compare 內；人力統計表以接口檔先行；其餘未建 |

## 檔案

| 檔案 | 用途 | 需要您確認或維護嗎 |
|---|---|---|
| `build.py` | 建檔程式：讀四個系統的產出 → 彙整 → 產生網頁，並印出建檔檢核 | 不需改；更新資料時執行 |
| `template.html` | 網頁樣板（版面與互動） | 不需改 |
| `data/manpower_extra.csv` | **新增人力資料接口檔**（約用、勞務承攬、勞動派遣等） | **要**：日後在此填入資料 |
| `output/index.html` | 產出的整合入口網頁（單一檔案，可離線開啟） | 由程式產生，不要手改 |

## 用法

```bash
python3 portal/build.py
```

第二層任何一個系統更新後，重跑上面這一行即可。畫面會印出檢核結果，例如：

```
機關主檔            585 個機關，機關代碼缺 0、重複 0
官職等檢核對上      579 個；未對上 6 個
主管機關統計對上    32/34 個部會
新增人力資料接口    0 列有效，0 個問題
```

## 接口檔欄位（`data/manpower_extra.csv`）

一列＝一個機關、一個年度、一種人力類別的一個數字。以 `#` 開頭的列會略過。

| 欄位 | 說明 |
|---|---|
| 年度 | 民國年 |
| 基準日 | 例如 115-12-31 |
| 機關代碼 | 須存在於機關主檔；不存在者該列不採用並列入問題清單 |
| 機關名稱 | 供人閱讀，系統以代碼為準 |
| 人力類別 | 約用／勞務承攬／勞動派遣／聘用／約僱／技工／工友／駕駛／其他 |
| 口徑 | 本機關／含所屬 |
| 人數 | 數字 |
| 來源、備註 | 文字 |

## 上線方式（尚未執行，待決定）

整合入口要與四個系統放在同一個 GitHub Pages 網站，「四系統並列」才能把原畫面嵌進來。
做法是在 `.github/workflows/pages.yml` 的「組合網站內容」加一行，並在 `paths` 加上 `portal/output/index.html`：

```yaml
mkdir -p site/portal && cp portal/output/index.html site/portal/index.html
```

如此整合入口網址為 `/portal/`，現行四個網址完全不變。

## 驗證紀錄（2026-11-20）

比照 `pages.yml` 在本機組出完整網站後，以瀏覽器自動化實測：

- 機關一頁式：農業部顯示編制員額 409；查「農糧署」得 A19010000G、五個區塊齊全，並標示預算與實有數字為農業部主管機關合計。
- 部會總覽：34 個部會皆有列。
- 四系統並列：組織法規系統開在「同級比對」並帶入農糧署；官職等系統直接顯示農糧署檢核結果。
- 接口檔：以 4 列測試資料驗證，2 列有效並出現在機關頁與部會加總；代碼不存在、類別不在清單、名稱與主檔不同三種情形皆列入問題清單。測試資料未留在正式輸出。
- 手機寬度（400px）與深色模式：各分頁無橫向溢出，無主控台錯誤。

## 已知限制

- 資料是從四個系統的網頁內解出來的，任一系統改了內嵌資料的寫法就要調整 `build.py`。正式化時應改為各系統輸出固定格式的資料檔。
- 預算員額與實有人數只到主管機關（部會）層級，不是單一機關。
- 契約人力統計有 105 個分組（舊名、合計列、非行政院機關）對不到機關主檔。
