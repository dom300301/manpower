### 已有的能力
- 便宜偵測（`check_updates.py`）：異動日、FileId 存否、廢止、未收錄。
- 受影響機關重做（`add_agencies.py --replace`）。
- PDF byte hash（`verify_tables_online.py`）、PDF 文字解析與逐列比對（`reparse_pdfs.py`）。
- 人工 override 機制與證據欄位（`manual_fixes.json`）。
- 兩階段提交與 `source_commit`／SHA-256 標示；離線單檔 HTML。
- 穩定機關 ID：總表 `機關代碼`（人事總處機關代碼表，585 筆無空值）；法規 ID：pcode；附件 ID：FileId。

### 缺少的能力
1. **manifest**：沒有一份「每個機關採用哪個 pcode／FileId／版本／hash／施行日」的清單；`編制表來源` 只存 URL，`組織法規連結` 以全形「；」串接（本輪已拆為來源陣列，但未存 hash／日期）。
2. **語意 hash**：只有 byte hash；PDF 重新上傳但內容相同（如臺中醫院新版 115-10-30 與舊版逐列相同）會被視為變更。
3. **修正／公布／施行分離**：只有 `最新異動日`；施行日、廢止、被取代未結構化（P2 計畫 A2 項）。
4. **依賴表**：共用準則（227 機關掛多法）改一處會影響哪些機關、不影響哪些，目前無表；掛接本身尚有 213 筆待審（P2 A1）。
5. **override 失效機制**：`manual_fixes` 不綁來源 hash／版本期間；來源改版後不會自動變「差異待審」。
6. **新設／改制 ID 與前後繼關係**：例外分頁有 29 筆「已由新組織法取代」（含代碼表沿革），但未進資料模型；新機關靠人工寫 `new_agencies.json`。
7. **受影響閉包重算**：現在不是全量重解析（只有異動機關），但建檔必然全量；可接受。缺的是「變更 → 受影響機關清單 → 只重解析這些」的明確計算與報告。
8. **OCR**：無；影像 PDF 一律人工轉錄（已有 6 個機關走此路，流程可行但無工具支援）。
9. **批次建表腳本與來源清單**不在 repo。
10. **網頁內「更新按鈕」**：線上版是 GitHub Pages 靜態單檔，無後端，瀏覽器不能執行 Python 或寫 repo；按鈕只能（a）顯示 manifest 的更新狀態、（b）連到 GitHub Actions 的「Run workflow」手動觸發一個只產報告的檢查流程（需登入 GitHub，不需金鑰）。不建議做成「按一下就更新資料並發布」。

## 二、最小 manifest 欄位（提案，單一 JSON 檔 `manifest/sources.json`）

```json
{
  "schema": 1,
  "generated_at": "2026-11-07T12:00:00+08:00",
  "master": {"path": "data/組織法編制表_總表_20261031.xlsx", "sha256": "…"},
  "agencies": [
    {
      "agency_id": "A05000000C",            // 機關代碼（穩定 ID）
      "name": "國防部",
      "lineage": {"predecessors": [], "successors": [], "basis": null},   // 新設／改制：前後繼／取代關係，依機關代碼表沿革
      "laws": [
        {"role": "組織法規", "pcode": "F0000001", "name": "國防部組織法",
         "promulgated": "2012-12-12", "amended": "2024-05-15", "effective": "2013-01-01",
         "effective_basis": "沿革末筆「定自…施行」", "status": "開放資料未標廢止",
         "open_data_modified": "20240515", "articles_hash": "sha256(條文正規化文字)"},
        {"role": "處務規程", "pcode": "F0010001", "...": "..."}
      ],
      "staffing_table": {
        "pcode": "F0000080", "file_id": "0000383280", "url": "…LawGetFile.ashx?FileId=0000383280",
        "byte_sha256": "…", "semantic_sha256": "sha256(正規化後的 (單位,職稱,官等,職等,員額原文,備註) 列序列)",
        "effective": "2024-01-01", "effective_basis": "附註「本編制表自…生效」", "fetched_at": "2026-10-31",
        "superseded": [{"file_id": "0000368769", "effective": "2023-11-16", "replaced_at": "2026-11-07"}]
      },
      "shared_law_dependencies": ["L0000053"],     // 本機關採用的共用法規 pcode（只列「相符／人工確認」者）
      "overrides": [
        {"fix_id": "mf-0123", "bound_to": {"file_id": "0000427371", "semantic_sha256": "…"},
         "scope": {"序": 29, "欄位": ["職稱"]}, "valid_from": "2026-11-07", "valid_until": null}
      ]
    }
  ],
  "shared_laws": {
    "L0000053": {"name": "衛生福利部各醫院組織準則", "applies_to": ["L…醫院機關代碼…"], "pending": ["…待審機關…"]}
  }
}
```

要點：
- `agency_id` 用機關代碼；法規用 pcode；附件用 FileId。三者皆已存在於總表或開放資料，不需新造。
- hash 兩層：`byte_sha256`（便宜、先比）與 `semantic_sha256`（解析後正規化，用來判斷「重傳但內容相同」）。
- 日期三欄分離：`promulgated`／`amended`／`effective`，各附 `basis`；解析不到留空並標待核，不猜。
- `shared_law_dependencies` 只收「相符／人工確認」的掛接（P2 A1 的輸出），待審者放 `shared_laws[pcode].pending`，不算依賴。
- `overrides` 綁 `bound_to`（FileId＋semantic hash）＋`scope`＋期間；來源 hash 不同即視為「override 待審」，不套用、不刪除。
- manifest 由 `build_dataset` 現有資料加 `verify_tables_online` 的 hash 產生，不上 DB、不開服務。

## 三、dry-run 入口規格（提案，命令名稱待定）

`python3 update_dryrun.py --manifest manifest/sources.json --master data/…xlsx [--offline] [--scope all|changed|agency:<id>] --out reports/dryrun_<日期>/`

執行順序與停止條件（成本由低到高，未變即停）：
1. **開放資料層**（必跑，約 2 個 JSON 下載）：比 pcode 的 `LawModifiedDate`、附件 FileId 存否、`LawAbandonNote`。無差異 → 寫報告「無變更」後停止。
2. **附件 byte 層**（只對第 1 層有差異的 FileId）：下載 PDF 比 `byte_sha256`。相同 → 記「重傳同檔」停止。
3. **語意層**（只對 byte 不同者）：pdfplumber 解析 → `semantic_sha256`；相同 → 記「內容相同（版面重排）」，只更新 manifest 的 FileId／日期，不動明細。不同 → 產生逐列 diff（新增／刪除／改值）。
4. **文字不可讀**（只對語意層解析失敗頁）：標「需人工轉錄／OCR」，不自動處理；LLM 或人工只看這些難列與 diff。
5. **影響閉包**：變更的 pcode → 依 manifest `shared_law_dependencies` 反查受影響機關；變更的 FileId → 該機關；改制／取代 → 前後繼機關。只列、不重算。
6. **override 檢查**：受影響機關的 `overrides` 若 `bound_to` 與新 hash 不符 → 列「override 待審」。
7. **輸出**：報告（見第五節）＋`pending_updates.json`（沿用現有格式，餵 `add_agencies.py --replace`）。不改總表、不改 manual_fixes、不建檔、不發布。

dry-run 不等於發布：真正更新仍是「人工核准 → `2_更新資料` → 處理 override 待審 → `3_建檔` → 分支 PR → 合併」。


## 四、測試計畫（dry-run／manifest 實作時的驗收）
1. **共用法規只影響適用機關**：fixture 改 `L0000053`（各醫院準則）的 articles_hash → 受影響清單＝`shared_laws.L0000053.applies_to`，不含老人之家等待審掛接機關。
2. **override hash 改即失效**：fixture 把臺中醫院 `staffing_table.semantic_sha256` 改一字 → 序 29 的 override 進「待審」，建檔時不套用、不刪除，該機關標「override 待審」不可比較。
3. **已公布未施行不提前生效**：fixture 法規 `amended` 為今日、`effective` 為未來日 → manifest 狀態「已公布未施行」，明細不更新，報告列「待施行」。
4. **區間／unknown 不硬算**：行政院 635–637、黨產會 9（兼任 36–38）、unknown 括號列在 dry-run 與重建後不變（沿用 P1 測試）。
5. **控制列／共用額不重計**：臺中醫院 217（控制列）、合併計列 794 列重建後不變、不重複加總。
6. **P0／P1 fixtures**：財政部 213、農藥所 79、恆春 94、玉里 465、軍備局 68、工程會 149–199、未取得 0、不可比較 2；資料層、P1 單元、控制列、前端四套測試全數維持。
7. **來源按鈕版本一致**：manifest `staffing_table.file_id` ＝ 頁面 PDF 按鈕 FileId ＝ 來源核對狀態文字之 FileId；`superseded` 只以文字呈現。
8. **未變即停**：fixture 開放資料無差異 → 報告 `stopped_at: layer1`，無任何下載、無 pending。
9. **重傳同檔**：byte 相同 → `stopped_at: layer2`；內容相同版面重排 → `layer3`，只更新 manifest。

### 受影響 diff 報告格式（`diff.md`）
```
# 更新 dry-run 差異報告（<日期>，manifest <sha>，開放資料 <UpdateDate>）
## 停止層級：layer3（內容未變）／layer3（有差異）
## 受影響機關（N）
| 機關代碼 | 機關 | 變更來源 | 類型 | 舊 | 新 | 建議動作 | override 待審 |
| A… | 衛生福利部臺中醫院 | FileId | 附件重傳 | 0000368769 | 0000427371 | 只更新 manifest | 0 |
## 逐列差異（只列 semantic 不同者）
| 機關 | 序 | 欄位 | 舊值 | 新值 | 來源頁 |
## 不受影響但掛接待審（不列入閉包）
## 需人工轉錄／OCR 頁
## 已公布未施行（待施行日）
```

### 人工核准
- dry-run 報告以分支提交並開 PR（只含 reports/ 與 manifest 變更）；審查者在 PR 回覆「同意更新：機關清單」。
- 核准後才跑 `2_更新資料`（只對清單機關）、處理 override 待審（逐筆改綁新 hash 或刪除）、`3_建檔`、兩階段提交、PR 審查、合併發布。監測（dry-run）與發布（合併）永遠分開。

### 回滾
- 資料：總表以日期檔名保留（`data/…_<日期>.xlsx`），回滾即指回前一檔重建；manifest 與 manual_fixes 隨 git 版本回退。
- 網站：Pages 由預設分支 `output/index.html` 決定，`git revert` 產物提交後推送即回到前一版；每版 `source_commit`／SHA-256 可對照離線 zip。

## 六、關於「網頁內更新按鈕」的建議
- 可做：頁面「指標說明與資料狀態」分頁加一塊「資料更新狀態」，讀同站 `manifest.json`（建檔時一併產出）：顯示 manifest 日期、開放資料 UpdateDate、上次 dry-run 結果摘要與連結；另放一個連到 GitHub Actions「檢查更新（只產報告）」流程的 Run workflow 連結（`workflow_dispatch`，需 GitHub 登入，不需在頁面放任何金鑰）。
- 不建議：在頁面放「一鍵更新並發布」。靜態頁沒有執行環境，若透過 Actions 自動改資料並發布，等於把監測等同發布，違反本案「人工核准後才發布」原則。

完成盤點，停止。待您同意後再做最小 manifest 與 dry-run。
